# PG 均衡：分别新增 1、2、3 个 OSD 的对比

每种情况从相同的 node1/node2 八个 OSD 独立开始，重新创建测试池并装载数据；不是从 8→9→10→11 连续扩容。新增四个的结果如在表中，来自此前已完成的正式测试。

每组 4096 个 4 MiB 对象，三副本、128 PG、并发 32。关闭压缩、PG 自动调整及测试池 scrub，不创建快照。

按池 flat 权重控制 node3 的参与子集，新增 N 个即选择 OSD 8 至 8+N-1；未加入的叶子权重保持 0。初始装载时 node3 桶权重为 0，装载完成后一次性恢复为所选叶子权重之和。全局 12 个 OSD 全程 up/in，既有 .mgr 池不受此池权重影响。

理想估算使用客户端数据量 D、初始三副本数据量 3D：

```text
理想迁移量 = 3D × N / (8 + N)
理想累计放大 = 1 + N / (8 + N)
```

主指标为全部 OSD 的 Messenger 接收字节增量 / (3D)，包含协议头、事务元数据和控制消息，结果不扣空闲背景。这里的“实测数据迁移量”取 push_out_bytes，它是发送侧恢复数据计数；每组均与 PG 映射推导的必要新增副本字节完全相等。

| 新增 OSD | 初始接收放大 | 累计数据写入路径放大 | PG 映射推导放大 | 均衡期间客户端写入 B | 完整校验对象数 |
|---:|---:|---:|---:|---:|---:|
| 1 | 1.000479 | 1.132738 | 1.132731 | 0 | 4096 |
| 2 | 1.000469 | 1.198735 | 1.198730 | 0 | 4096 |
| 3 | 1.000474 | 1.247645 | 1.247640 | 0 | 4096 |
| 4 | 1.000463 | 1.357997 | 1.357992 | 0 | 4096 |

数据写入路径放大使用 BlueStore write_big_bytes + write_small_bytes，包括 OSD 内部对象写入，不能按池过滤，是独立交叉核对项，不代表 SSD 内部写入。所有组均在均衡窗口之后读回校验全部对象，并完成测试池、权重集和规则清理，恢复原 CRUSH 内容、flags 和 balancer 状态。

每种情况只有一次正式运行，没有重复实验置信区间。各组使用独立池，池 ID 不同会影响具体 PG 映射；实际 PG 分布及旧 OSD 之间的额外迁移都能使结果偏离理想值。
