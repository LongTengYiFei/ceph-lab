# Workload A / B：六块混合 SSD B 写入对照

两轮均使用真实 YCSB 0.17.0 CoreWorkload、同一 RADOS 4 KiB 覆盖写 binding、
4 GiB 数据、1 GiB 缓存目标、三副本、32 线程、目标 10,000 ops/s、300 s 预热和 300 s 正式阶段。
两轮分别创建临时池；测量六块 SSD B 整盘 Linux 块层写入，不包含后端数据 SSD A。

| 指标 | Workload A | Workload B |
|---|---:|---:|
| 目标 READ / UPDATE | 50% / 50% | 95% / 5% |
| 成功 READ | 1,498,081 | 2,845,924 |
| 成功 UPDATE | 1,497,674 | 149,891 |
| 成功写入 D（GiB） | 5.713173 | 0.571789 |
| SSD B 整盘 W（GiB） | 105.907230 | 41.697376 |
| W / D | 18.537375 | 72.924438 |
| W / (3D) | 6.179125 | 24.308146 |
| 正式负载 SSD B 写入（GiB） | 99.878952 | 39.562962 |
| 排空尾部 SSD B 写入（GiB） | 6.028278 | 2.134415 |
| 正式窗口自然逐出 | 716,692 | 492,999 |
| 正式窗口 agent_flush | 81,750 | 0 |

B 的整盘绝对写入比 A 少 60.63%，但成功 UPDATE 载荷少了 89.99%。
因此 B 的 W/D 更高，不能把这个倍数解释为 B 向 SSD 写入了更多数据。READ 触发的缓存提升及其元数据也进入 W，READ 字节不进入 D。

## B 的 LV 块层分账

| 区域 | 写入 GiB | 占 SSD B 总量 |
|---|---:|---:|
| 后端 DB/WAL LV | 2.990639 | 7.172% |
| 缓存 OSD LV（对象与自身 DB/WAL） | 38.706738 | 92.828% |

本轮六盘物理计数与全部 LV 计数之和的残差为 0 B。
A 未采集 LV 块层计数，不将 A 的内部路径估计冒充直接 LV 测量。

## 相同 OSD 内部路径计数的交叉对照

| 路径 | A（GiB） | B（GiB） |
|---|---:|---:|
| 后端 BlueFS DB/日志 | 22.673916 | 2.990295 |
| 缓存 BlueFS DB/日志 | 64.454548 | 32.145061 |
| 缓存对象写入路径 | 18.769181 | 6.557644 |

内部计数用于近似归因，不与物理计数再叠加。B 的缓存 LV 写入中，较大的部分仍是缓存 OSD 自身的 BlueFS DB/日志路径。

## 比较范围与校验

- A 在预热期间取消提升限速；B 在装载前就取消限速。两轮正式期间均固定不限速，但预热历史不同；临时池 ID 和 PG 映射也不同。
- 两轮都是单次探索性测试，没有证明稳定状态或提供重复实验置信区间，不能把所有差异只归因于读写比例。
- 两轮正式起点均保留预热脏缓存。主窗口包括正式阶段至尾部排空，尾部可能回写预热遗留脏对象；D 只含正式成功 UPDATE。
- B 正式阶段发生自然逐出，未发生自然 agent_flush；停止负载后通过临时池阈值设置排空，尾部写入已计入 W。
- 两轮客户端失败/CRC 错误均为 0，均完整读取后端 1,048,576 条记录检查大小和 CRC32。
- B 的 SMART 主机写入交叉核对覆盖 4/6 盘；全部 6 盘的物理块层与 12 个 LV 计数完整。指标不代表 NAND/FTL 写放大。
- B 临时池删除、提升限速与 balancer 恢复完成；永久池、完整 config dump 和 flags 与实验前一致，12 OSD up/in、129 PG active+clean，OSD 删除队列均为 0。
